  <name>Task 1: shadow_monitor.py — 4 métricas SHAD-02 (winsorizado, Jaccard@100, alert rate, off-hours)</name>
  <files>scripts/shadow_monitor.py, tests/test_shadow_monitor.py</files>
  <action>
Script que descarga los datos shadow del WRITE ClickHouse local (filtrando `scoring_mode IN ('shadow_old','shadow_new')` sobre una ventana de N días) a un DataFrame pandas y computa las 4 métricas en Python (evita SQL complejo de window functions anidadas — el research advierte que puede requerir ajuste por versión de CH).

Funciones (reusar patrones exactos de `retrain_frame_v1.py` líneas ~525-545 para winsorización y `exp_frame_feature_small.py` para spearman):

1. `load_shadow_df(ch_client, days: int) -> pd.DataFrame` — SELECT de payment_id, scoring_mode, percentile, amount_usd, is_anomaly, currency, frame_flags, payment_created_at WHERE scoring_mode IN ('shadow_old','shadow_new') AND scored_at >= now() - INTERVAL {days} DAY. FINAL no necesario en anomaly_scores (MergeTree append-only con dedup token).

2. `compute_alert_rate_by_segment(df) -> pd.DataFrame` — SHAD-02-A: por (currency, scoring_mode): total, alerts=sum(is_anomaly), alert_rate=alerts/total.

3. `compute_top5_bias(df, model) -> dict` — SHAD-02-B, métrica ROBUSTA winsorizada: filtrar sub=df[scoring_mode==model]; k5=int(len(sub)*0.05); top5_idx = sub.percentile.nlargest(k5).index; amounts=sub.amount_usd (float64); p999=np.percentile(amounts,99.9); wins=np.clip(amounts,None,p999); top5_wins=np.clip(sub.loc[top5_idx,'amount_usd'],None,p999); ratio=top5_wins.mean()/wins.mean() (guard mean>0). Devolver {model, top5_wins_ratio, p999, n}. NUNCA usar ratio de medias crudo (cola pesada lo invalida — decisión locked 01-03).

4. `compute_off_hours(df, model) -> dict` — SHAD-02-C: off-hours local aproximado. `is_off_hours_loc` no se persiste; aproximar con `toHour(payment_created_at)` (UTC, facilities UTC-3..UTC-8). Además reportar `tz_missing_rate` = fracción de filas con `JSONExtractBool(frame_flags,'timezone_missing')` (parseando frame_flags JSON en pandas para el modelo shadow_new; shadow_old tiene frame_flags='').

5. `compute_jaccard_at_k(df, k=100) -> float` — SHAD-02-D: old=set top-k payment_id por percentile de shadow_old; new=set top-k de shadow_new; return len(old&new)/len(old|new) (guard conjuntos vacíos -> 1.0).

`main()` con argparse (`--days`, default configurable) que conecta al WRITE CH (mismas env vars ANOMALY_SCORES_CH_* que main.py), corre las 5 funciones y imprime un reporte legible + opcionalmente vuelca JSON. NO conectar al READ prod.

Tests en `tests/test_shadow_monitor.py` sobre DataFrames sintéticos in-memory (sin ClickHouse): (a) compute_top5_bias con cola pesada devuelve ratio winsorizado < ratio crudo; (b) compute_jaccard_at_k con overlap conocido devuelve el valor esperado; (c) alert_rate_by_segment agrega correctamente.
  </action>

`source venv/bin/activate && pytest tests/test_shadow_monitor.py -q` pasa. `python scripts/shadow_monitor.py --days 1` corre sin error contra el CH local (si hay datos shadow del 04-01; si no hay filas, reporta n=0 sin crashear). `make lint` limpio.
  </verify>
  <done>Las 4 métricas SHAD-02 se computan sobre datos shadow del WRITE CH local; top-5% bias es winsorizado p99.9; Jaccard@100 y alert-rate-por-segmento correctos; el script no toca prod y no crashea con 0 filas.</done>

<task type="auto">
  <name>Task 2: shadow_gate.py — gate go/no-go SHAD-03 con guard temporal/volumen (INSUFFICIENT_DATA)</name>
  <files>scripts/shadow_gate.py, tests/test_shadow_gate.py</files>
  <action>
Script de decisión go/no-go. Existe desde día 1 pero aborta si no hay >=2 semanas de datos — separación estructural código/evaluación (pitfall #5).

Thresholds hardcodeados (mismos que el bias_report de Fase 1, decisión locked 01-03):
```python
GATE_TOP5_MAX_RATIO = 4.0        # top-5% winsorizado < 4x (baseline 11.79x)
GATE_OFF_HOURS_MIN = 0.03        # off-hours local >= 3%
GATE_OFF_HOURS_MAX = 0.07        # off-hours local <= 7% (~4-5%)
GATE_SPEARMAN_MIN = 0.90         # Spearman ranking >= 0.90
GATE_ALERT_RATE_DELTA_MAX = 0.02 # delta alert rate <= 2pp por segmento
MIN_SHADOW_DAYS = 14
MIN_SHADOW_ROWS = 500            # Jaccard@100 + Spearman necesitan volumen (open question #3)
```

Funciones:
1. `compute_spearman(df) -> float` — merge de percentiles shadow_old/shadow_new por payment_id; si len(merged)<30 return nan; `rho,_ = spearmanr(pct_old, pct_new)`; return float(rho). Reusar de exp_frame_feature_small.py.

2. `evaluate_gate(df) -> dict` — PRIMERO el guard temporal/volumen:
```python
days_span = (df['scored_at'].max() - df['scored_at'].min()).days  # o payment_created_at
n_rows = len(df)
if days_span < MIN_SHADOW_DAYS or n_rows < MIN_SHADOW_ROWS:
    return {"status": "INSUFFICIENT_DATA", "days_span": days_span, "n_rows": n_rows,
            "min_days": MIN_SHADOW_DAYS, "min_rows": MIN_SHADOW_ROWS}
```
Si hay datos suficientes: computar los 4 criterios reusando las funciones de `shadow_monitor.py` (importar compute_top5_bias, compute_off_hours, compute_alert_rate_by_segment) + compute_spearman. Devolver `{"status": "PASS"|"FAIL", "criteria": {top5_ratio_new, top5_ratio_old, off_hours_new, spearman, max_alert_rate_delta}, "checks": {top5_pass, off_hours_pass, spearman_pass, alert_delta_pass}}`. status='PASS' sii los 4 checks pasan. El criterio central: top5_ratio de frame-v1 (shadow_new) < 4.0 Y materialmente menor que el del champion (confirma en datos reales la reducción 15.7x -> ~3.3x del offline).

`main()` con argparse conecta al WRITE CH local (env vars ANOMALY_SCORES_CH_*), carga el df completo de shadow (todos los días disponibles), corre evaluate_gate, imprime PASS/FAIL/INSUFFICIENT_DATA con los 4 criterios y sus valores, y sale con exit code 0 (PASS), 1 (FAIL), 2 (INSUFFICIENT_DATA) para uso en CI/operativo. NO tocar READ prod.

Tests en `tests/test_shadow_gate.py` sobre DataFrames sintéticos: (a) df con days_span<14 -> status INSUFFICIENT_DATA (no PASS aunque las métricas serían buenas); (b) df con n_rows<500 -> INSUFFICIENT_DATA; (c) df sintético con >=14 días, >=500 filas, ranking correlacionado y sesgo bajo -> PASS; (d) df con top5_ratio del new >= 4.0 -> FAIL con top5_pass=False; (e) compute_spearman con <30 pares devuelve nan.

# Guía del .gitignore para ML Projects

Esta guía explica qué archivos están siendo ignorados y por qué.

## 📋 Resumen Rápido

El `.gitignore` está organizado en secciones para máxima claridad:

1. **Environment & Secrets** - Credenciales y configuración sensible
2. **Python** - Archivos generados por Python
3. **Jupyter Notebook** - Checkpoints y outputs
4. **Data Files** - Datasets (generalmente muy grandes)
5. **Models & Checkpoints** - Modelos entrenados (muy grandes)
6. **Logs & Outputs** - Archivos de log
7. **MLflow & Tracking** - Artifacts de experimentos
8. **IDE & Editors** - Configuraciones de IDEs
9. **Testing & Coverage** - Resultados de tests
10. **Type Checking & Linting** - Cache de herramientas
11. **Documentation** - Builds de documentación
12. **Deployment** - Archivos de deployment
13. **Temporary Files** - Archivos temporales
14. **Project Specific** - Específicos del proyecto
15. **Cloud & Services** - Configuraciones cloud

## 🔒 Archivos Críticos Ignorados

### Secrets y Credenciales (¡MUY IMPORTANTE!)

```
.env                    # Variables de entorno
*.key                   # Llaves privadas
*.pem                   # Certificados
credentials.json        # Credenciales
secrets.yaml           # Secrets
```

⚠️ **NUNCA commitees estos archivos** - Contienen información sensible.

## 📊 Archivos de Datos Ignorados

### Por qué ignoramos datos

Los archivos de datos están ignorados porque:

1. **Tamaño**: Los datasets ML suelen ser muy grandes (GB/TB)
2. **Privacidad**: Pueden contener información sensible
3. **Reproducibilidad**: Los datos se deben poder regenerar
4. **Costo**: Git no maneja bien archivos grandes

### Formatos ignorados

```
*.csv                   # Archivos CSV
*.parquet              # Apache Parquet
*.h5, *.hdf5           # HDF5
*.pkl, *.pickle        # Pickle files
*.joblib               # Joblib serialization
*.npy, *.npz           # NumPy arrays
```

### Excepciones permitidas

Si necesitas versionar datos pequeños:

```gitignore
# En .gitignore, descomenta:
!data/raw/sample_*.csv      # Permite sample_data.csv
!*_config.csv               # Permite archivos de configuración
```

Límite recomendado: **< 10 MB**

## 🤖 Modelos Ignorados

### Por qué ignoramos modelos

```
models/saved_models/*       # Modelos productivos
models/experiments/*        # Modelos experimentales
*.pkl, *.joblib            # Archivos serializados
*.h5, *.pth, *.pt          # Checkpoints de DL
```

Razones:
- Muy grandes (pueden ser 100+ MB)
- Reproducibles entrenando de nuevo
- Mejor gestión con MLflow o Model Registry

### Alternativas para compartir modelos

1. **MLflow Model Registry**
   ```python
   mlflow.sklearn.log_model(model, "model")
   ```

2. **Cloud Storage**
   ```bash
   aws s3 cp model.pkl s3://bucket/models/
   ```

3. **Git LFS** (Large File Storage)
   ```bash
   git lfs track "*.pkl"
   ```

4. **DVC** (Data Version Control)
   ```bash
   dvc add models/model.pkl
   ```

## 📓 Jupyter Notebooks

### Qué se ignora

```
.ipynb_checkpoints/         # Checkpoints automáticos
*-checkpoint.ipynb          # Notebooks checkpoint
```

### Qué NO se ignora

```
notebooks/*.ipynb           # Tus notebooks SÍ se versionan
```

### Limpieza de notebooks

El pre-commit hook `nbstripout` limpia automáticamente:
- Outputs de celdas
- Metadata innecesaria
- Números de ejecución

Esto mantiene los diffs limpios.

## 📝 Logs y Outputs

### Ignorados

```
logs/*                      # Todos los logs
*.log                       # Archivos log
*.out, *.err               # Outputs de procesos
```

### Por qué

- Se regeneran en cada ejecución
- Pueden ser muy grandes
- Contienen información específica del entorno

## 🔧 Configuración de IDEs

### Ignorados

```
.vscode/                   # Visual Studio Code
.idea/                     # PyCharm
*.sublime-*               # Sublime Text
```

### Por qué

Cada desarrollador usa diferentes:
- IDEs
- Configuraciones personales
- Extensiones
- Temas

## 🧪 Testing y Coverage

### Ignorados

```
.pytest_cache/            # Cache de pytest
.coverage                 # Coverage data
htmlcov/                  # HTML coverage reports
```

Se regeneran con:
```bash
pytest --cov=src
```

## 🎯 Excepciones y Casos Especiales

### Permitir archivos específicos

Si un archivo está ignorado pero quieres incluirlo:

```gitignore
# En .gitignore
*.csv                      # Ignora todos los CSV

# Pero permite uno específico
!important_config.csv      # Excepción con !
```

### Ignorar todo excepto algunos

```gitignore
# Ignora todo en una carpeta
data/raw/*

# Pero mantén el README
!data/raw/README.md
!data/raw/.gitkeep
```

## 📦 Git LFS Setup (Opcional)

Para archivos grandes que DEBES versionar:

### 1. Instalar Git LFS
```bash
brew install git-lfs      # macOS
# o
apt-get install git-lfs   # Linux

git lfs install
```

### 2. Track archivos grandes
```bash
git lfs track "*.pkl"
git lfs track "*.parquet"
git lfs track "*.h5"
```

### 3. Actualizar .gitignore
```gitignore
# Comenta las líneas que quieres versionar
# *.pkl                   # Ahora manejado por LFS
```

### 4. Commit
```bash
git add .gitattributes
git add models/model.pkl
git commit -m "Add model with LFS"
```

## ✅ Verificación

### Comprobar qué está siendo ignorado

```bash
# Ver archivos ignorados
git status --ignored

# Verificar si un archivo específico está ignorado
git check-ignore -v data/raw/test.csv

# Listar todos los archivos tracked
git ls-files
```

### Limpiar archivos ignorados

```bash
# Ver qué se eliminaría
git clean -ndX

# Eliminar archivos ignorados
git clean -fdX
```

## 🚨 Errores Comunes

### 1. Archivo ya está tracked

Si agregaste archivos antes de configurar .gitignore:

```bash
# Dejar de trackear pero mantener local
git rm --cached data/raw/big_file.csv

# Commit
git commit -m "Stop tracking big file"
```

### 2. .gitignore no funciona

```bash
# Limpiar cache de Git
git rm -r --cached .
git add .
git commit -m "Refresh .gitignore"
```

### 3. Commitee accidentalmente un secret

```bash
# CUIDADO: Esto reescribe historia
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch .env" \
  --prune-empty --tag-name-filter cat -- --all

# Mejor: Usa herramientas como BFG Repo-Cleaner
```
